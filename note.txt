## 4. Data Fetching and Logic
The component fetches repayment data when it mounts or when `userId` changes, using the `useEffect` hook:

```jsx
useEffect(() => {
  if (!userId) {
    setError('User ID is missing');
    setLoading(false);
    return;
  }

  const fetchRepayments = async () => {
    try {
      setLoading(true);
      const response = await axiosInstance.get(
        API_PATHS.REPAYMENT.GET_REPAYMENT_BY_USER(userId)
      );
      
      if (!response.data.success) {
        throw new Error(response.data.message || 'Failed to fetch repayments');
      }
      
      setRepayments(response.data.repayments);
      setError(null);
    } catch (err) {
      setError(err.response?.data?.message || err.message || 'Failed to fetch repayments');
      if (err.response?.status === 401 || err.response?.status === 400) {
        // navigate('/login');
      }
    } finally {
      setLoading(false);
    }
  };

  fetchRepayments();
}, [userId, navigate]);
```

- **Validation**: Checks if `userId` exists; if not, sets an error and stops loading.
- **API Call**: Uses `axiosInstance` to fetch repayments for the given `userId`.
- **Error Handling**:
  - Checks `response.data.success` to ensure the API call was successful.
  - Catches errors and sets an error message, prioritizing `err.response?.data?.message`.
  - Plans to redirect to `/login` for 401 (unauthorized) or 400 (bad request) errors, though this is commented out.
- **State Updates**: Sets `repayments` on success, clears `error`, and sets `loading` to `false` in the `finally` block.
- **Dependencies**: The effect runs when `userId` or `navigate` changes.

**Logic for Filtering and Metrics**:
```jsx
const filteredRepayments = repayments.filter(rep => {
  if (activeTab === 'all') return true;
  return rep.loan.status === activeTab;
});

const totalPaid = repayments.reduce((sum, rep) => sum + rep.lastPayment, 0);
const activeLoans = [...new Set(repayments.map(rep => rep.loan._id))].length;
```

- `filteredRepayments`: Filters repayments based on the `activeTab` state. If `'all'`, includes all repayments; otherwise, matches `rep.loan.status` to `activeTab`.
- `totalPaid`: Aggregates the `lastPayment` field across all repayments.
- `activeLoans`: Uses `Set` to count unique `loan._id` values, representing the number of distinct loans.

## 6. Responsive Design
The component is optimized for smaller screens with the following changes:
- **Container**: Uses `max-w-4xl` to limit width, ensuring content fits on mobile.
- **Grids**: Stats cards switch to three columns at `sm` (640px); summary and activity sections remain single-column for clarity.
- **Table vs. Cards**: Table view is replaced with a card view on mobile (`block sm:hidden`) to avoid horizontal scrolling issues.
- **Typography**: Smaller font sizes on mobile (e.g., `text-xs sm:text-sm`, `text-2xl sm:text-3xl`).
- **Spacing**: Reduced padding and margins (e.g., `p-4`, `mb-6`) to save space.
- **Buttons**: Full-width on mobile for better tap targets.
- **Tabs**: Horizontal scrolling (`overflow-x-auto`) for narrow screens.

The `sm` breakpoint (640px) is used consistently to transition from mobile to desktop layouts, ensuring a smooth experience across devices.
